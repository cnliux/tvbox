- 返回键有两条互斥的消费路径：`PlayerScreen.kt` 根 `Box` 的 `onPreviewKeyEvent`（约 L737-753）在 `controlsVisible` 或 `controlsPanel != None` 时消费 BACK 并收起控件/面板；仅在两者都关闭时返回 `false`，事件才进入 Activity 的 `OnBackPressedDispatcher`，由页面 `BackHandler` 处理。同一次返回不会同时被两处消费。

- **独立文件**：`files/blocked_categories.json`。迁移时优先读取；文件缺失或解析失败回退偏好里的 `blocked_video_categories`。迁移后该文件只读保留，不再回写。
- **旧数据保留**：SharedPreferences XML 与各 JSON 串原样保留。正常读取只认 DataStore；仅当 DataStore 没有 `schema_version`（首次启动或上次迁移失败）时才用旧数据重试迁移，不做常规双读兜底。

### schemaVersion 与写入模型

- 起始值：旧 SharedPreferences 无版本，视为 `0`；迁移完成写 `1`（`SettingsSchema.LEGACY = 0`、`SettingsSchema.CURRENT = 1`）。
- 存储位置：Preferences DataStore，`files/datastore/app_settings.preferences_pb`；键名沿用旧命名，结构化字段仍以 JSON 字符串存储，读取复用同一套解析函数，保证迁移前后语义一致。
- **单写者串行**：迁移、`saveSettings`、`saveSpeedLatencies` 全部经同一 `Mutex` 串行，等价于单 actor；避免迁移写回覆盖用户刚保存的设置（此前专项 commit 与全量 save 的双写冲突在此收敛为一个入口）。

### 迁移失败与回滚

| 场景 | 行为 |
| --- | --- |
| 读旧数据失败 | 不写 `schema_version`；本次若旧数据可读则直接返回旧快照，否则返回默认值；下次读取自动重试 |

## 功能增强第 1 轮（2026-11-07）—— 16KB 页对齐

**背景**：Android 15 起 16KB page size 成为硬性要求，上架渠道会拦截 LOAD 段未按 16384 对齐的 so。v1.3.48 发布包内的 `libgojni.so` 实测 3 个/4 个 LOAD 段 `Align=0x1000`，lint 基线中有 3 条 `Aligned16KB`（同一问题重复记录）。

### 改动

| 文件 | 改法 |
| --- | --- |
| `tools/bind-platform-live.ps1` / `tools/bind-platform-live.sh` | `gomobile bind` 的 `-ldflags` 由 `-s -w` 改为 `-s -w -extldflags=-Wl,-z,max-page-size=16384`，由 NDK lld 按 16384 生成 `p_align` |
| `app/lint-baseline.xml` | 删除 3 条已失效的 `Aligned16KB` 记录 |

`stripPlatformLiveAar` 的 `llvm-strip --strip-unneeded` 只移除符号表，不改写 program headers，实测剥离前后对齐不变，无需额外处理。

### 真实产物校验

- 重新生成 AAR（`gomobile bind`，arm64-v8a）后，`llvm-readelf -l` 对该 AAR 内 `libgojni.so` 的 4 个 LOAD 段均输出 `Align 0x4000`。
- 执行 `:app:stripPlatformLiveAar` 后再次解包校验，4 个 LOAD 段仍为 `Align 0x4000`（AAR 5,995,342 字节）。
- `:app:assembleDebug` 产物 `app/build/outputs/apk/debug/app-debug.apk`（35,596,037 字节）内 `lib/arm64-v8a/libgojni.so` 解包后 `llvm-readelf -l` 同样为 4 个 `LOAD ... Align 0x4000`。
- `zipalign -c -P 16 4 app-debug.apk` 返回 0，APK 内未压缩 so 的 zip 对齐也满足 16KB。
- lint 不再报告 `Aligned16KB`，并提示 3 条 baseline 记录「not found in the project」；删除后该提示消失（过滤数量由 6 errors / 71 warnings / 6 hints 变为 6 / 68 / 6）。
  - 备注：任务描述为「4 条过期记录」，本机 lint 实际只识别出 3 条，即上述 3 条 `Aligned16KB`，无第 4 条可删除的过期项，按实测结果清理。
