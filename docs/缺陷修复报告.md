## 设置存储单一数据源迁移（2026-11-07）—— DataStore（改进项，非缺陷修复）

### 迁移覆盖范围

- **独立文件**：`files/blocked_categories.json`。迁移时优先读取；文件缺失或解析失败回退偏好里的 `blocked_video_categories`。迁移后该文件只读保留，不再回写。
- **旧数据保留**：SharedPreferences XML 与各 JSON 串原样保留。正常读取只认 DataStore；仅当 DataStore 没有 `schema_version`（首次启动或上次迁移失败）时才用旧数据重试迁移，不做常规双读兜底。

### schemaVersion 与写入模型

- 起始值：旧 SharedPreferences 无版本，视为 `0`；迁移完成写 `1`（`SettingsSchema.LEGACY = 0`、`SettingsSchema.CURRENT = 1`）。
- 存储位置：Preferences DataStore，`files/datastore/app_settings.preferences_pb`；键名沿用旧命名，结构化字段仍以 JSON 字符串存储，读取复用同一套解析函数，保证迁移前后语义一致。
- **单写者串行**：迁移、`saveSettings`、`saveSpeedLatencies` 全部经同一 `Mutex` 串行，等价于单 actor；避免迁移写回覆盖用户刚保存的设置（此前专项 commit 与全量 save 的双写冲突在此收敛为一个入口）。

### 迁移失败与回滚

| 场景 | 行为 |
| --- | --- |
| 读旧数据失败 | 不写 `schema_version`；本次若旧数据可读则直接返回旧快照，否则返回默认值；下次读取自动重试 |
| 写 DataStore 失败 | `updateData` 原子写入，失败不产生半成品、不写 `schema_version`，旧数据保持可读；下次读取重试 |
| 迁移未完成时 `saveSettings` | 抛 `IOException`，避免把「未迁移的默认值」写成 `schema_version=1` 而永久跳过迁移 |
| DataStore 文件损坏 | `ReplaceFileCorruptionHandler` 以空偏好重建；`schema_version` 随之丢失，下次读取用保留的旧 SharedPreferences 重新迁移 |
| 回退旧版本 APK | 旧 SharedPreferences 未被修改，旧版本仍可读到升级前设置（升级后新改动不会回灌） |

## 功能增强第 18 轮（2026-11-07）—— 详情请求失败不再只剩「重试」

**实机反馈**：详情请求失败（系统代理制造失败）后页面退回首页，既无错误页也无「返回」按钮、无失败提示。

### 排查结论

- 静态复核 `openDetail`：`getDetailProgressively` 的异常在 `catch (Throwable)` 中被转成 `detailError`，主源无数据时也会写「影片详情不存在」，两处都会让 `screen` 保持 `Detail`。**代码里没有「失败后自动回首页」的分支**，唯一回首页的入口是 `goBack()`（系统返回/返回键）。
- 真正缺失的是失败页的可操作性：原 `ErrorState` 只有「重试」，没有标题、也没有「返回」，用户无法判断这是失败态；若设备上失败提示尚未渲染就按了返回，观感即为「直接退回首页」。
- 因此本轮不猜「异常被吞」，而是把失败态做成明确的、可离开的页面，并加诊断日志用于设备侧确认分支。

| 问题 | 文件 | 改法 |
